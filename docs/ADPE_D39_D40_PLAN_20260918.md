# ADPE 属性 Query 前置审计方案：D39 / D40

日期：2026-09-18。

## 1. 目标

RCR 前置审计已经证明属性是主要错误来源，但固定 ICAQ Top-1 属性决策不稳定。本阶段
不训练新模型，检查 ICAQ 的**软属性分数**是否能够区分 Troika 最常见的 hard negative：
同一个对象下，真实属性与 Troika 错误预测属性之间的差异。

如果 ICAQ 虽然 Top-1 不稳定，但在这些 hard negative 上经常给真实属性更高分，则说明
问题主要是属性 Query 的判别边界和校准，需要训练新的 ADPE，而不是继续搜索 patch 位置。

## 2. 固定输入与协议

- 数据集：UT-Zappos validation。
- seed0：Troika `P0_ut_cls_seed0` + ICAQ `B1_icaq_seed0`。
- seed1：Troika `P9_ut_cls_seed1` + ICAQ `B2_icaq_seed1`。
- 强制 `msaq_pair_gate=0`，不让 ICAQ 改变 Troika 原组合预测。
- 只读取 validation 图像；不训练，不读取 test 图像。

## 3. 统计内容

1. Troika 属性混淆矩阵及最常见真实属性-错误属性对；
2. 在“Troika 属性错、对象对”样本上，ICAQ 真实属性分数减去 Troika 错误属性分数的 margin；
3. margin 为正的 hard negative 比例；
4. ICAQ 与 Troika 原属性分支的 Top-1/Top-2/Top-5 属性覆盖；
5. 真实组合在 Troika Top-2/5/10 的候选覆盖；
6. 正确属性进入候选后，局部分数是否能把它排在错误属性前面。

## 4. 预注册继续门槛

D39 和 D40 必须同时满足：

- 在“属性错、对象对”样本中，ICAQ 真实属性分数高于 Troika 错误属性分数的比例至少为
  `10%`；
- 该正 margin 样本占全部 validation 至少 `5%`；
- ICAQ 真实属性 Top-5 覆盖至少 `70%`。

三个条件都通过，才实现 ADPE。任一 seed 未通过，则关闭当前 ICAQ 软分数路线，不训练
ADPE，转向互补视觉骨干或新的监督来源。

## 5. ADPE 预定方向（仅在门槛通过后启动）

- 图像生成 Query，不使用真实标签选择 Query；
- 所有候选属性统一计算；
- 同对象错属性作为主要 hard negative；
- 同属性不同对象用于属性/对象解耦约束；
- patch dropout、局部裁剪和颜色扰动一致性；
- 类别平衡属性损失；
- Troika 高置信正确样本保持约束；
- 最终只增加候选相关的属性-对象关系 residual，不使用全局属性加性 gate。
