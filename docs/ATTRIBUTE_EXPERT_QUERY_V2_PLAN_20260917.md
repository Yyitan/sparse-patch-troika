# 属性专家 Query V2：诊断与下一版决策方案

日期：2026-09-17

## 1. 已知事实

OCAQ V1 已证明监督 Query 可以形成明显不同的 patch 关注区域，组合残差也在两个种子上产生正 AUC 变化。但最终属性准确率下降，属性残差单独使用时只带来约 0.06%-0.09% 的属性提升。

下一步不扫描 Query 数、层数或邻域大小，而是先回答：属性能力不足来自 Query 本身没有学会属性，还是多个 Query 已经有互补信息但路由/对象融合丢失了信息。

## 2. D15/D16 固定 checkpoint 属性专家诊断

固定 Q1/Q2 最佳 checkpoint，只评估 validation，不训练、不读取 test。比较：

1. Troika 原始属性头 top-1。
2. OCAQ 完整属性残差后的属性头 top-1。
3. 真实对象条件下的聚合局部属性 top-1。
4. Troika 预测对象条件下的局部属性 top-1。
5. 对象后验加权的局部属性 top-1。
6. 四个单独 Query 的真实对象条件属性 top-1。
7. 任一 Query 预测正确的 oracle 上界。
8. 按目标属性分数选择 Query 后的上界。
9. 每个属性类别上的原属性头、局部属性和 oracle 正确率。

### 决策门槛

- 若“任一 Query oracle”比聚合局部属性高至少 3 个百分点，说明 Query 间存在可用互补，下一版优先做**属性文本条件路由**。
- 若 oracle 只高不到 3 个百分点，且真实对象局部属性仍低于 Troika 原属性头，说明四个通用 Query 本身判别不足，下一版改成**属性文本自身作为 Query**，每个候选属性主动寻找对应视觉证据。
- 若真实对象局部属性高于原属性头，但预测对象/后验融合明显下降，则优先解决对象候选与融合校准。

以上判断只依据双种子重复结果，不根据单个种子或测试集选择路线。

## 3. 预备的 V2 方向

如果诊断支持“属性文本自身作为 Query”，下一版采用 Text-Grounded Attribute Query：

- 第 12 层对象 Query 继续提供可训练对象区域。
- 对每个候选 `(属性文本, 对象上下文)` 构造一个属性 Query，而不是使用 4 个与属性无关的通用槽位。
- 属性 Query 对第 6 层 patch 做 cross-attention，对象核心和 3x3 邻域只作为软偏置。
- 第一阶段只训练局部属性专家，按真实对象条件 validation 属性准确率选模，不训练组合 gate。属性损失固定为普通交叉熵与逆平方根类别频率加权交叉熵各 0.5，兼顾总体准确率和长尾属性；不扫描类别权重。
- 只有局部属性专家在两个种子都超过 Troika 原属性头至少 1 个百分点，才进入第二阶段的 CLS 融合与组合评测。

该两阶段训练把“学会属性”和“如何融合”分开，防止组合 CE 把局部 Query 训练成只会修正 pair 排序的分支。
