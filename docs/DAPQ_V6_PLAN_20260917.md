# DAPQ V6：密集属性原型监督的前景 Patch Query

日期：2026-09-17。基于Troika与MSAQ独立副本开发；原始代码不修改。所有阶段先使用
validation-only，未满足双seed门槛前禁止读取test。

## 1. 已确认的事实

1. MSAQ属性Query已经定位真实鞋主体：两个seed最大注意力patch前景核心命中率为
   98.6310%/99.5644%，空间定位不是瓶颈；
2. MSAQ冻结版AUC变化为+0.7096/+0.0704点，只有seed0稳定；
3. 当前局部属性分类中，每个属性Query视觉特征只与同名属性文本计算一个对角标量，再把
   不同Query的标量做CE；
4. 该损失没有要求真实属性Query的视觉特征在所有属性文本原型中仍正确分类，缺少直接的
   跨类别表征约束。

## 2. DAPQ结构

空间部分完全继承MSAQ：layer12语义key、layer6细节value、属性文本Query与sparsemax。
不使用对象mask、foreground硬mask、中心ring或手工top-k。

对每个属性Query得到视觉特征 `v_a` 后，与所有属性文本原型计算矩阵：

`S[b,a,k] = cosine(v[b,a], text[k]) * scale`

- 原局部属性logit仍为矩阵对角线 `S[b,a,a]`，与MSAQ严格对照；
- 对真实属性 `y`，新增密集原型logits `S[b,y,:]`，要求真实属性Query提取出的视觉特征在
  所有属性原型中预测为 `y`；
- primitive attribute CLS分支保持原样，不加入局部residual；
- composition分支仅保留零初始化的属性级pair residual，这是D21/D22中唯一跨seed同向信号。

## 3. 损失与参数

冻结完整Troika与CLIP，只训练MSAQ和composition gate，约590万参数。

- 原Troika composition CE：权重1.0；
- 对角局部属性标准CE与Balanced Softmax：各0.5后合并，再乘0.5；
- 真实Query密集属性原型标准CE与Balanced Softmax：各0.5后合并，权重1.0；
- 不训练primitive attribute gate，不训练对象分支，不解冻视觉主干。

## 4. 验证顺序

### D31/D32：固定MSAQ权重的表征审计

加载M1/M2，只计算真实属性Query在全部属性文本原型上的micro/macro。用于判断现有局部特征
是否已有原型判别能力，不改变权重。

### A0：工程检查

- 零gate精确复现CLS；
- dense logits形状为`B×A×A`，对角线与旧local logits一致；
- 密集原型损失能反传至layer6/layer12投影和Query；
- primitive attribute logits不被局部gate直接修改；
- validation/test协议隔离。

### A0c：seed0一轮机制筛查

允许进入正式双seed的条件：

- dense true-query macro较训练前明显改善，且不发生单类塌缩；
- validation AUC相对CLS下降不超过0.2点；
- sparse attention继续保持有效前景选择；
- primitive macro下降不超过0.5点。

若dense true-query准确率异常高，必须追加图像错配捷径审计：保持真实标签和query编号不变，
把输入图像替换为验证集中固定偏移的另一张图。若错配图像下dense macro仍保留正常值的80%以上，
说明模型主要利用属性query身份而非patch证据，禁止进入A1/A2，并重构监督方式。

### A1/A2：固定五轮双seed

正式通过条件：两个seed validation AUC均至少高于各自CLS 0.2点，且primitive macro下降
均不超过0.5点。任一失败，不读取test、不扫描损失权重或层位。

## 5. 后续视觉Adapter阶段的进入条件

只有当DAPQ使两个seed的dense true-query macro都明显提高，但AUC门槛仍因局部分数兼容性
失败，才允许下一阶段解冻最后两层视觉Adapter，并加入CLS蒸馏约束。若密集监督本身不能改善
局部表征，则直接停止该方向，不通过扩大模型容量掩盖监督无效。
