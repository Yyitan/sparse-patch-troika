# 前景对象定位可行性：UT-Zappos 白背景审计

日期：2026-09-17。仅 validation；不训练、不读取 test。

## 为什么重新验证对象定位

此前D17/D18否定的是由当前CLIP文本attention产生的对象区域：错误对象和跨图区域并不更差，
所以不能把它称为对象定位。UT-Zappos实际为商品白背景图，若数据本身允许可靠前景提取，
则“先对象、后属性patch和邻域”仍有一个未验证的独立前提。

## F0：零训练前景审计

固定规则：像素任意RGB通道小于245记为非白；取最大8连通域作为前景。全验证集统计：

- 非白像素覆盖、最大连通域覆盖及其对全部非白的占比；
- 前景bbox宽高面积、贴边比例；
- 映射到ViT-L/14在224输入下的16×16后非零patch与核心patch覆盖；
- 均匀抽取24张图保存叠加图人工审计。

## 通过条件

仅当最大连通域对非白像素的中位占比高、无效box极少、bbox不普遍贴边，且叠加图显示主体
鞋子而非背景阴影或文字时，才允许做固定的foreground core/ring与全patch对照。白色鞋面与
白背景混淆会被明确记录；没有可信前景来源时不进入训练。

## F0b 结果：前景来源可用，但patch网格以16×16为准

ViT-L/14在224输入产生16×16 patch。最初F0把patch网格误记为14×14，原图连通域统计有效、
但其patch统计作废；已在F0b以正确网格重跑。3214张验证图均存在最大前景连通域，最大连通域
占全部非白像素中位99.9837%，bbox贴边仅10.0809%。16×16下前景核心patch中位占37.50%，
非零patch中位占48.05%。24张叠加图人工检查显示框覆盖鞋主体。

因此独立foreground mask本身通过可行性审计，但它是否能改善模型仍须先看已有属性注意力
是否已自然使用主体。
