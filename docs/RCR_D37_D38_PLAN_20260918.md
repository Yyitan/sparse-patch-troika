# RCR 前置机会审计方案：D37 / D38

日期：2026-09-18。

## 1. 目的

前面的 ICAQ 已证明 patch 分支能够提取依赖当前图像的属性信息，但把局部属性分数作为
属性级加性 residual 融入 Troika 时，双 seed 的组合排序收益不稳定。本阶段先不训练新模型，
只回答一个更具体的问题：**ICAQ 的局部属性证据，是否恰好出现在 Troika 组合预测错误且
对象判断正确的样本上，从而具备修正真实组合错误的空间。**

只有这个交集在两个 seed 上都足够大，才允许实现显式属性-对象关系重排器 RCR。

## 2. 固定输入

- 数据集：UT-Zappos validation。
- seed0 Troika：`experiments/P0_ut_cls_seed0/val_best.pt`。
- seed1 Troika：`experiments/P9_ut_cls_seed1/val_best.pt`。
- seed0 ICAQ：`experiments/B1_icaq_seed0/icaq_best.pt`。
- seed1 ICAQ：`experiments/B2_icaq_seed1/icaq_best.pt`。
- 将 `msaq_pair_gate` 强制置零，确保组合分数严格来自原 Troika；ICAQ 只提供局部属性诊断。
- validation-only，不读取 test 图像，不训练，不调参。

## 3. 诊断指标

### 3.1 Troika 错误类型

按 Troika 最终组合 Top-1 的属性和对象拆分全部组合错误：

1. 属性错、对象对；
2. 属性对、对象错；
3. 属性和对象都错。

该结果判断当前主要瓶颈是否确实包含可由属性细节修正的部分。

### 3.2 候选覆盖

- 真实组合在 Troika Top-1/2/5/10 中的覆盖率；
- 仅在 Troika Top-1 错误样本上统计 Top-2/5/10 恢复覆盖；
- ICAQ 真实属性在局部属性 Top-1/2/3/5 中的覆盖率。

如果真实组合连 Top-10 都很少出现，则小型重排器缺少候选；如果 ICAQ 属性 Top-K 覆盖高，
则可以考虑让局部属性证据参与候选关系比较，而不是直接加到所有同属性组合上。

### 3.3 核心可修正交集

分别使用两种对象来源：

- Troika 最终组合 Top-1 所携带的对象；
- Troika 独立 object CLS 分支 Top-1。

统计：

`Troika组合错误 ∩ 对象正确 ∩ ICAQ局部属性Top-1正确`

并构造零训练 oracle：原组合预测正确，或“ICAQ 属性 + Troika 对象”同时正确，则记为正确。
报告 oracle 相对原始组合 Top-1 的绝对提升。该 oracle 仅表示可用证据上限，不是正式方法。

## 4. 预注册继续门槛

主判据固定使用“独立 object CLS 分支 + ICAQ 属性”，D37 和 D38 必须同时满足：

1. oracle 相对 Troika 原始组合 Top-1 至少提升 `0.02`，即 2 个百分点；
2. 核心可修正交集至少占全部 validation 样本 `0.02`，即 2%。

任一 seed 未通过：停止 RCR 训练，结论为现有局部属性证据没有稳定落在关键组合错误上。

两个 seed 都通过：进入 RCR，固定先做以下结构，不扫描 patch 数量或空间邻域：

- 保留 Troika CLS 与 ICAQ 局部属性表征；
- 对每个候选属性-对象组合显式计算关系分数；
- 对关系分数做属性、对象双向中心化，去掉纯属性和纯对象边际项；
- 使用同对象错属性、同属性错对象的 hard negative；
- 对高置信 Troika 正确样本施加保持约束；
- residual gate 零初始化。
