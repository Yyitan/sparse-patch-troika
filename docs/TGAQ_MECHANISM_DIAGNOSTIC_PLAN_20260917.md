# TGAQ 固定 Checkpoint 机制消融方案

日期：2026-09-17

## 目的

TGAQ 双种子正式训练没有超过 Troika 原属性头。训练后对象 Query 准确率达到
75.67%/78.06%，但正确对象相对错误对象的属性分数 margin 为负，说明失败可能来自
两种不同原因：

1. 对象区域先验把属性 Query 推向了错误或过窄的 patch；
2. 第 6 层 patch 表征和当前属性 Query 本身缺少足够属性判别力。

本轮固定 T1/T2 最佳 checkpoint，不重新训练、不调参、不读取 test，只在 validation
上做机制控制。

## 固定对照

| 编号 | 属性 Query | 区域偏置 | 要回答的问题 |
|---|---|---|---|
| M0 | 属性文本 + 对象上下文 | 正确候选对象区域 | 已训练 TGAQ 的复现基准 |
| M1 | 属性文本 + 对象上下文 | 无区域偏置 | 对象区域约束是否本身有益 |
| M2 | 属性文本 + 对象上下文 | 错误对象区域 | 区域是否具有对象语义特异性 |
| M3 | 属性文本 + 对象上下文 | 跨图区域 | 区域是否只是空间/显著性先验 |
| M4 | 仅属性文本 | 正确候选对象区域 | 单独保留区域能否提供对象条件 |
| M5 | 仅属性文本 | 无区域偏置 | 纯全局属性 Query 的判别能力 |
| M6 | 原始属性文本相似度 | 第 6 层 patch mean/max | 不经过已训练 Query 的表示下界 |

M2 对对象维循环移位，M3 对 batch 维循环移位。所有对照使用同一数据顺序、同一
checkpoint 和同一真实对象条件评价口径。

## 判定规则

- 若 M1 或 M5 稳定超过 M0：当前对象区域偏置有害，下一版应去掉强制定位，改成
  属性 Query 先全局找证据，再用对象信息做软校准。
- 若 M0 稳定超过 M1/M2/M3，但仍低于 Troika：定位有信息，主要瓶颈是属性表示或
  长尾监督；下一版保留区域但改损失和表示学习。
- 若 M2/M3 与 M0 接近：区域不具对象语义特异性，不应继续围绕对象 mask 调参。
- 若所有 Query 版本都接近或低于 M6：训练后的 Query/MLP 没有形成有效属性表示，
  下一步应重做属性视觉表征，而不是继续改融合权重。

本轮只形成机制结论，不允许因为单个种子的小幅差异进入 test 或融合实验。
