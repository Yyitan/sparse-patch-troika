# 2026-09-16 第三轮：固定 checkpoint 的 patch 互补性诊断

## P6 设计

加载P0最佳验证checkpoint，不再训练参数。属性/物体分支保持原CLS解耦输出，
只在组合分支融合CLS和末层patch分数：

`score = (1 - alpha) * score_cls + alpha * score_patch`

验证集预先扫描max/top-k2和alpha=0.1/0.25/0.5/0.75/1.0，并把纯CLS加入
候选；只允许验证AUC选出一个配置，再在测试集评测一次。alpha=0必须精确复现
P0验证AUC，否则运行失败。该实验只回答已有P0表征中patch是否提供直接互补证据，
不回答重新训练后的选择器上限。

## P6 结果

| 配置 | 验证 AUC |
|---|---:|
| CLS，alpha=0 | **50.5867** |
| max，alpha=0.10 | 50.4953 |
| top-k2，alpha=0.10 | 50.4762 |
| max，alpha=0.25 | 50.1335 |
| top-k2，alpha=0.25 | 50.0420 |
| max，alpha=0.50 | 48.1493 |
| top-k2，alpha=0.50 | 48.4977 |
| max，alpha=1.00 | 12.8060 |
| top-k2，alpha=1.00 | 15.6428 |

验证集选择为纯CLS。测试集只评测了该候选，复现P0测试AUC 42.5326；没有用
测试集选择融合权重。P6峰值分配3,428,064,768 bytes。

结论：当前P0末层原始patch的class-conditioned max/top-k2不是可直接叠加的互补
证据。即使10%权重也略微降低验证AUC，并且权重越大退化越明显。因此停止继续扫描
k和融合系数，转向原路线E4的层位诊断，检查属性/局部信息是否在中层更可用。

## P7 多层诊断

独立版本`code_v4/`在一次视觉前向中截取ViT第6/12/18/24层。最终CLS、CMT、
属性/物体分支均不变，只替换组合分支最终patch匹配所用层位。候选为max/top-k2，
alpha=0.1/0.25/1.0。第24层alpha=0.1必须复现P6对应结果，作为正确性检查。
验证集仍可选择纯CLS，测试集只评测验证集选出的一个候选。

## P7 结果

第24层复现检查通过：max/top-k2、alpha=0.1的验证AUC分别精确复现P6的
50.4953和50.4762。验证集最优候选为第6层top-k2、alpha=0.25：

| 配置 | 验证 AUC | 相对CLS |
|---|---:|---:|
| CLS | 50.5867 | 0.0000 |
| layer6 max，alpha=0.10 | 50.9885 | +0.4017 |
| layer6 top-k2，alpha=0.10 | 51.0472 | +0.4605 |
| layer6 top-k2，alpha=0.25 | **51.2975** | **+0.7107** |
| layer12 top-k2，alpha=0.10 | 51.0413 | +0.4545 |
| layer18 max，alpha=0.10 | 50.7733 | +0.1866 |
| layer24 max，alpha=0.10 | 50.4953 | -0.0915 |

只在测试集评测验证选出的layer6 top-k2、alpha=0.25，测试AUC为42.5113，
而P0 CLS为42.5326，差-0.0213个百分点，基本持平而非测试提升。P7峰值分配
3,908,419,072 bytes。该单seed固定checkpoint诊断说明中层patch比末层patch更可能
提供互补信息，但尚不能证明端到端训练或跨seed有效。
